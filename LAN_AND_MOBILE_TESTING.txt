================================================================================
          HOW TO RUN AND TEST DUALSTREAM ON MOBILE PHONES & OTHER DEVICES
================================================================================

To run this application on different devices (e.g., streaming from your phone or 
viewing the host dashboard from a tablet/another laptop), you need to solve two 
technical requirements:
1. Network accessibility (letting other devices connect to your host machine).
2. Browser Security Rules (WebRTC requires HTTPS/Secure Contexts on mobile).

Here are the step-by-step methods to implement this.

--------------------------------------------------------------------------------
METHOD 1: USING NGROK / LOCAL TUNNEL (RECOMMENDED & EASIEST)
--------------------------------------------------------------------------------
Because mobile browsers block webcam/screen share APIs on non-secure (HTTP) 
connections, using a tunnel that provides public HTTPS URLs is the easiest and 
most reliable method.

1. Install ngrok (https://ngrok.com) or use localtunnel (npm install -g localtunnel).
2. Open two separate terminal windows on your host computer:
   
   * In Terminal 1, tunnel the Backend Signaling Server (Port 3001):
     ngrok http 3001
     (Take note of the generated HTTPS URL, e.g., https://abcd-123.ngrok-free.app)

   * In Terminal 2, tunnel the Frontend Dev Server (Port 5173):
     ngrok http 5173
     (Take note of the generated HTTPS URL, e.g., https://wxyz-789.ngrok-free.app)

3. Update the Environment variables so the frontend knows to point to the 
   Backend's secure ngrok URL instead of localhost:
   * Create a file named `frontend/.env.local` and add:
     VITE_SIGNALING_URL=https://abcd-123.ngrok-free.app
   
   * Create a file named `backend/.env` and add:
     FRONTEND_URL=https://wxyz-789.ngrok-free.app

4. Restart your project:
   npm run dev

5. On your phone:
   - Open the frontend ngrok URL: `https://wxyz-789.ngrok-free.app/client`
   - Start webcam / screen sharing (it will work because it is HTTPS!).
6. On your other device:
   - Open: `https://wxyz-789.ngrok-free.app/host`
   - You will see the live streams relayed seamlessly.

--------------------------------------------------------------------------------
METHOD 2: TESTING OVER LOCAL WI-FI (LAN)
--------------------------------------------------------------------------------
If both your computer and phone are connected to the exact same Wi-Fi router, you
can access the servers directly via your computer's local IP address (e.g., 192.168.1.50).

Step 2.1: Find your Computer's Local IP Address
- On Windows: Open Command Prompt, type `ipconfig`, and look for "IPv4 Address" 
  under your Wi-Fi adapter (e.g., `192.168.1.50`).
- On Mac/Linux: Open terminal and type `ifconfig` or `ip a`.

Step 2.2: Configure Vite to Listen on the Network
By default, Vite only listens to `localhost`. You need to expose it:
1. Update `package.json` in the root workspace or frontend, or simply run:
   npm run dev -- --host
   (Or run `npx vite --host` in the `frontend` folder).
2. Create `frontend/.env.local` to tell the app where the backend is:
   VITE_SIGNALING_URL=http://<YOUR_COMPUTER_IP>:3001
3. Create `backend/.env` to allow CORS from your local IP:
   FRONTEND_URL=http://<YOUR_COMPUTER_IP>:5173

Step 2.3: Bypass Insecure Origin Restrictions on Mobile Chrome (Android)
If you open `http://192.168.1.50:5173/client` on a phone browser, the webcam button
will be disabled or throw an error because it is HTTP.
- On Android Chrome:
  1. Navigate to `chrome://flags/#unsafely-treat-insecure-origin-as-secure`
  2. Enable the flag.
  3. In the text box, enter your computer's local address:
     `http://192.168.1.50:5173`
  4. Relaunch Chrome. The browser will now treat it as secure and allow the webcam.
- On iOS (iPhone/iPad):
  iOS Safari does not support bypassing HTTP secure context rules. You MUST use 
  Method 1 (HTTPS Tunneling) or configure self-signed certificates.

--------------------------------------------------------------------------------
METHOD 3: PRODUCTION DEPLOYMENT
--------------------------------------------------------------------------------
To host the project permanently so anyone can connect from their phones anywhere 
in the world:

1. Build the production bundles:
   - Frontend: `npm run build:frontend` (generates the static files in `frontend/dist`).
   - Backend: `npm run build:backend` (transpiles TS server files to JS).

2. Deploy the backend:
   - Deploy the Node.js signaling server to Render, Heroku, or an AWS EC2 instance.
   - Configure a domain name with an SSL certificate (HTTPS is mandatory).

3. Deploy the frontend:
   - Deploy the `dist` folder to Netlify, Vercel, or AWS S3.
   - Set the env variable `VITE_SIGNALING_URL` to point to your deployed backend URL.

4. Setup a TURN Server:
   - Mobile networks (LTE/5G) and home Wi-Fi networks use symmetric NATs. Direct 
     P2P connection will fail in ~30-50% of real-world scenarios.
   - To guarantee connection, install or lease a TURN server (e.g., Coturn, or 
     third-party services like Xirsys or Twilio Network Traversal).
   - In `frontend/src/services/webrtcService.ts`, update the `iceServers` array 
     to include your TURN server credentials:
     ```typescript
     iceServers: [
       { urls: 'stun:stun.l.google.com:19302' },
       { 
         urls: 'turn:your-turn-server.com:3478',
         username: 'your-username',
         credential: 'your-password'
       }
     ]
     ```
